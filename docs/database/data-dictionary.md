## The schema overview: the views people read

Plain-English views over DCRS and the Audit Assistant, one row per real-world thing, for people to read. Nothing here holds data of its own: every view reads the live tables, so a change shows at once. Read-only for the role overview_viewer.

### overview.dcrs_accounts

*A view, owned by postgres.* One row per DCRS sign-in account: who it is, what it may see, whether it is switched on, and when it last signed in. Never the password.

| Column | Type | What it holds |
|---|---|---|
| `person_id` | text | The account's id in DCRS. It never changes. The Audit Assistant keeps it as the person's external id. |
| `name` | text | The person's name, as DCRS shows it and writes it in records. |
| `email` | text | The email address the person signs in with. |
| `role` | text | Super admin (sees and manages everything) or Staff. |
| `departments` | text | The departments whose documents the account may see, by full name, or Every department. |
| `department_codes` | text | The same departments by their short codes (for example HR, QC). Empty when the account sees every department. |
| `account_status` | text | Active, or Switched off (the account cannot sign in). |
| `must_change_password` | yes or no | True while the account still has a password the administrator set, which the person must change at the next sign-in. |
| `created_factory_time` | date and time | When the account was made, in factory time. |
| `created_utc` | date and time | When the account was made, in UTC. |
| `last_sign_in_factory_time` | date and time | When the person last signed in to DCRS, in factory time. Empty if never. |
| `last_sign_in_utc` | date and time | When the person last signed in to DCRS, in UTC. Empty if never. |

### overview.records

*A view, owned by postgres.* One row per DCRS record, that is one filled-in (or still blank) copy of a form for one date. Live records only, never the demonstration data.

| Column | Type | What it holds |
|---|---|---|
| `record_id` | text | The record's id in DCRS. It never changes. The record opens in DCRS at #/record/&lt;this id&gt;. |
| `document_id` | text | Which form this is a copy of, by its id in DCRS (for example daily-pest-monitoring). |
| `format_number` | text | The form's format number as printed on the paper (for example F/HR/17). TO BE CONFIRMED when the plant has not given one yet. |
| `document_name` | text | The form's name (for example Daily Pest Control Monitoring Record). |
| `department_code` | text | The short code of the department that owns the form (for example HR). |
| `department_name` | text | The full name of the department that owns the form (for example Human Resources). |
| `record_date` | date | The date the record is for (its due date). |
| `status` | text | Where the record stands, in DCRS's own words: Scheduled, Due, In Progress, Submitted, Pending Verification, Verified or Rejected (sent back). |
| `submitted_by` | text | Who submitted the record for verification. |
| `submitted_factory_time` | date and time | When it was submitted, in factory time. |
| `submitted_utc` | date and time | When it was submitted, in UTC. |
| `verified_by` | text | Who verified (approved) the record. |
| `verified_factory_time` | date and time | When it was verified, in factory time. |
| `verified_utc` | date and time | When it was verified, in UTC. |
| `sent_back_by` | text | Who last sent the record back for changes. |
| `sent_back_factory_time` | date and time | When it was last sent back, in factory time. |
| `sent_back_utc` | date and time | When it was last sent back, in UTC. |
| `sent_back_reason` | text | Why it was last sent back, in the words of the person who sent it back. |
| `created_factory_time` | date and time | When the record was made, in factory time. |
| `created_utc` | date and time | When the record was made, in UTC. |
| `last_changed_factory_time` | date and time | When the record last changed in any way, in factory time. |
| `last_changed_utc` | date and time | When the record last changed in any way, in UTC. |
| `last_changed_by` | text | Who made the latest change written in the record's history. Empty when its history is empty. |
| `history_entries` | whole number | How many entries the record's history holds: every edit, submission, verification, sending back and correction. |

### overview.findings

*A view, owned by postgres.* One row per internal CAPA finding (the Pest Control Inspection Findings Report). The status is the one people see in DCRS: Overdue is worked out from the target date, today.

| Column | Type | What it holds |
|---|---|---|
| `finding_id` | text | The finding's readable id, for example CAPA-2023-12-13-1: the report's date (with b, c ... when a date has more than one report), then the finding's number. The same id the DCRS API and the Audit Assistant use. It can change if a report is added earlier on the same date; finding_reference never does. |
| `finding_reference` | text | The finding's permanent reference, &lt;record id&gt;:&lt;finding's own id&gt;. It never changes. The DCRS API accepts it wherever it accepts the readable id. |
| `record_id` | text | The report (record) the finding is written in. It opens in DCRS at #/gap/&lt;this id&gt;. |
| `finding_number` | whole number | The finding's S.No on the report (its place in the list when no S.No is given). |
| `report_date` | date | The date of the report the finding is on. |
| `inspection_date` | date | The date of the inspection, as written on the report. |
| `finding` | text | What was found, in the inspector's words. |
| `comments` | text | Comments on the finding. |
| `corrective_action_by_contractor` | text | The corrective action the pest control contractor takes. |
| `corrective_action_by_plant` | text | The corrective action the plant itself takes. |
| `target_date` | date | The date by which the finding should be dealt with. |
| `action_date` | date | The date the action was actually taken (DCRS's Close button fills it in). |
| `verified_by_service_provider` | text | Who from the service provider verified the action. |
| `status` | text | Open, Overdue (past its target date with no action date), Closed or Verified: what DCRS shows today. |
| `stored_status` | text | The status as it was last saved in the record. It can say Open when the finding has since become overdue; the column status is the one to read. |
| `days_overdue` | whole number | How many days past its target date an overdue finding is. Empty unless the status is Overdue. |
| `source` | text | Internal (the plant's own inspection) or External (an outside audit, customer or regulator). |
| `report_status` | text | The status of the report the finding is on (In Progress, Pending Verification, Verified ...). A finding cannot be closed on a Verified or sent-back report until the report is reopened or resumed in DCRS. |
| `report_verified_by` | text | Who verified the report, once it is verified. |
| `last_changed_factory_time` | date and time | When the report last changed, in factory time. |
| `last_changed_utc` | date and time | When the report last changed, in UTC. |

### overview.pest_control_reports_by_day

*A view, owned by postgres.* One row per calendar day of the Daily Pest Control Monitoring Record (F/HR/17), from the first day DCRS holds to today, including the days with no record at all (status Not started).

| Column | Type | What it holds |
|---|---|---|
| `report_date` | date | The day. |
| `weekday` | text | The day of the week (Thursday is the factory's weekly day off). |
| `record_id` | text | That day's F/HR/17 record in DCRS. Empty when there is none. It opens at #/record/&lt;this id&gt;. |
| `status` | text | Not started when DCRS holds no record for the day; otherwise the record's status (Due, In Progress, Pending Verification, Verified ...). |
| `holiday` | yes or no | True when the record is marked as a holiday (no checking that day). Empty when there is no record. |
| `checked_by` | text | Who did the checking. |
| `time_of_checking` | text | The time of the checking, as written (hours:minutes). |
| `checkpoints_answered` | whole number | How many of the ten checkpoints are answered. |
| `rodents_caught` | whole number | How many rodents were found in the trap boxes that day. |
| `observations` | whole number | How many observations are written in the summary of actions. |
| `observation_details` | text | The observations: the date, what was seen, the action taken and remarks, one after another. |
| `submitted_by` | text | Who submitted the day's record for verification. |
| `submitted_factory_time` | date and time | When it was submitted, in factory time. |
| `verified_by` | text | Who verified the day's record. |
| `verified_factory_time` | date and time | When it was verified, in factory time. |

### overview.dcrs_activity

*A view, owned by postgres.* One row per line of DCRS's activity log, the archived lines included: who did what, on what, when and from which address. The log can never be changed or deleted.

| Column | Type | What it holds |
|---|---|---|
| `activity_id` | whole number | The line's number in the activity log. |
| `happened_factory_time` | date and time | When it happened, in factory time. |
| `happened_utc` | date and time | When it happened, in UTC. |
| `happened_date` | date | The day it happened, at the factory. |
| `person_id` | text | The DCRS account that did it. Empty for DCRS's own scheduled jobs (shown as System). |
| `person_name` | text | The name of the person who did it, as it was then. |
| `person_email` | text | The email of the person who did it, as it was then. |
| `action` | text | What was done, in DCRS's own words (for example Record edited, Document printed, Signed in). |
| `category` | text | The kind of action: Download, Print, Upload, Record change, Sign-in, Account, Escalation or Other. |
| `on_what` | text | What it was done on: usually the form's number, name and date. |
| `detail` | text | More about it: the note, the fields changed, the file name and so on. |
| `department_code` | text | The short code of the department the line is filed under. |
| `department_name` | text | The full name of the department the line is filed under. |
| `ip_address` | text | The network address the request came from. |
| `through_client` | text | The other system the person acted through (for example Audit Assistant). Empty when the person did it in DCRS itself. |
| `archived` | yes or no | True for a line the super admin has moved to the archive of old lines. |

| `happened_factory_time` | date and time | When it happened, in factory time. |
| `happened_utc` | date and time | When it happened, in UTC. |
| `happened_date` | date | The day it happened, at the factory. |
| `person_name` | text | Who did it. |
| `person_email` | text | The email of the person who did it. |

| `department_name` | text | The department that owns the document. |

| `through_client` | text | The other system it went through (for example Audit Assistant). Empty when it was done in DCRS itself. |
